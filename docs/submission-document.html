1. Overview

Toy Haven is a multi-page front-end store for collectible figurines, toys, board games and diecast model cars. It was built mobile-first with no frameworks: three organised stylesheets, one shared JavaScript core and one small script per page. The 24-product catalogue is a JSON array in js/data.js, so every listing, card, modal, basket row and order line is rendered from a single source of data.

Because there is no back end, every interaction that a real store would send to a server is instead written to localStorage: the basket survives a page refresh and a browser restart, the wishlist keeps a status per product, checkout writes an order into a local history, and the feedback form stores each message so the visitor can see exactly what was captured. The site is also a progressive web app — it can be installed to a home screen and previously visited pages keep working with no connection.

2. Planning and design

2.1 Approach

Every page was wireframed at 375px first and then widened, which is why the CSS contains only min-width media queries: the mobile layout is the default and larger screens add columns rather than remove them. The breakpoints used throughout are 40em (640px) for small tablets, 48em (768px) for the modal and footer, 55em (880px) where the navigation collapses into the animated hamburger, and 60em (960px) for the full desktop layout.

5. Testing

5.1 How the site was tested

  • Functional testing — the 48 test cases below were executed in Google Chrome 152 on macOS, against the deployed site and a local server.
  • HTML validity — every page submitted to the W3C Nu Markup Validation Service.
  • CSS validity — all three stylesheets submitted to the W3C CSS Validation Service (CSS level 3 + SVG profile).
  • Accessibility — WAVE and axe-core run on every page, in both light and dark themes, including the open modal and the invalid-form state.
  • Lighthouse — every page audited in both the mobile and desktop presets.
  • Responsiveness — checked at 320, 375, 414, 768, 1024, 1280 and 1600px.

Accessibility work that produced those results:

  • Landmarks on every page: header, nav, main, footer, plus a skip link.
  • A visible label for every form control, errors announced with role="alert" and linked by aria-invalid.
  • Descriptive alternative text on product images, and empty alt on the purely decorative hero backgrounds.
  • State exposed to assistive technology: aria-pressed on filter, heart and status buttons, aria-expanded on the hamburger and FAQ triggers, aria-current on the active page and slide.
  • The carousel marks hidden slides with aria-hidden and removes their links from the tab order.
  • The modal sets aria-modal, moves focus to its close button and returns focus to the trigger.
  • Toasts are announced politely through a live region instead of interrupting with alert().
  • All animation is disabled under prefers-reduced-motion, and both themes meet AA contrast.

6. Hosting and deployment

  1. The project was committed to a dedicated repository named toy-haven.
  2. GitHub Pages was enabled in Settings → Pages, deploying from the main branch, / (root) folder.
  3. The site is publicly available at https://nihmathullahmazhar.github.io/toy-haven/ and was re-tested after deployment.

All paths are relative, so the site works both at the repository sub-path on GitHub Pages and when served from the root of any other server.

7. Known limitations and future work

  • There is no back end, so orders, messages and subscriptions stay on the device that created them; clearing browser data clears them.
  • Payment is simulated. No card details are transmitted, stored or validated against a payment provider beyond format checks.
  • The catalogue is fixed at 24 products in js/data.js. It is deliberately shaped like an API response so it could be replaced with a fetch() call without touching the rendering code.
  • Product photography is replaced by original vector-style illustrations generated for this project, so no third-party images are used.
  • Possible next steps: pagination or infinite scroll for a larger catalogue, product reviews, and a background-sync queue so orders placed offline are sent when the connection returns.
